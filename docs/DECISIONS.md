# Decisions and rationale

Recorded against v0.2.1 on 2026-10-27; updated for v0.7.0 on 2026-10-28. These are implemented choices unless marked deferred. User goals are separate in [REQUIREMENTS.md](REQUIREMENTS.md).

Runtime storage is device/browser-specific; export/import is the transfer mechanism.                                                                                                                             |

Skills/resources are IDs and catalogs; engine code does not branch on science-fiction or fantasy names.                                                                                                                 |

Orders finish once and do not automatically repeat.                                                                                                                                                       |
| Separate real wait and fictional calendar                                  | A long interstellar journey can take minutes of play while advancing years in the setting. This is logistics fiction, not orbital or relativistic simulation. Accepted work does not expire during cryosleep.                                                                           |

## Alternatives and limits

The original Far Wake implementation used direct route endpoints, then exposed departure-world guidance. User feedback led to region-wide space departures instead; guidance alone did not satisfy the intended fiction. The engine retains both policies for other settings.

Hollowmere reuses generic mechanisms but has a separate themed UI, rather than a complete skin/configuration language. It currently imports shared UI styles. A data-only game authoring system is not implemented or required.

No roguelite loss/reset economy has been selected. Permanent unlocks, procedural mission construction, generator persistence and alternative ships need designs before implementation. See [ROADMAP.md](ROADMAP.md).

## Later direction: surprise onset

The user clarified on 2026-10-27 that a creature should sometimes be a surprise. The v0.3 implementation adds silent exposure from ordinary site exploration alongside the explicit specimen trigger. The user approved this plus a political discovery follow-up on 2026-10-28; explicit response warnings, no offline casualties and guaranteed recovery remain. [EVENTS.md](EVENTS.md) records the implemented selection rules and settlement claim. The claim waits for docking without stopping time; committing a recipient applies one-time payment and persistent faction standing. A durable ledger prevents repeat rewards. Larger event catalogs and a procedural galaxy remain deferred.

## Seeded names (v0.4)

Both games now generate crew, faction, region and location names from themed vocabularies using pure functions. Names have independent seeded domains and never consume combat/event RNG. Stable IDs and geography remain unchanged. Factories accept a saved generation version: 1 reproduces existing authored names/recruits; 2 is the default for fresh expeditions. No state-schema migration is needed because seed/version and crew names already persist. Vocabulary changes require a new compatible generation version. References in narrative resolve by identity after naming. See [NAMES.md](NAMES.md).

## Generated exploration sites (v0.5)

Generation 3 adds meaningful site profiles in both games while retaining v2 names and authored geography. Trait components alter effort, returns, hazards and optional specialist approaches. Explicit selection can explore sites out of order; the quick activity uses the next direct approach. No specialist path is mandatory. Existing Job.site/timer/reward/risk fields commit choices, so no state migration is required. Generations 1/2 retain their old site IDs and job outcomes. Contextual discovery weights vary opportunities without exposing hidden onset. See [SITES.md](SITES.md).

## Discovery-derived contracts (v0.6)

Contextual follow-ups are additive to generation 3 so current site expeditions gain work without a reset. Templates derive IDs, source, work and recipient from frozen site profiles. Discovery-gated offers and accepted-contract-gated activities reuse existing state/mission accounting. Work grants no immediate reward; filing pays once. Completed work cannot be abandoned, preventing replay without a separate receipt schema. Generations 1/2 remain unchanged. See [MISSIONS.md](MISSIONS.md).

## Generated layouts (v0.7)

New expeditions use generation 4, retaining authored story-anchor IDs and the first local/outbound journey while varying other connections and optional regions/places. Connected local and regional graphs guarantee structural reachability; each region has a service hub. The seed/version reconstructs catalogs without changing state schema. Generations 1–3 remain frozen, verified with full-definition hashes captured before implementation. Domain-separated layout streams leave outcome randomness independent. Actual-graph campaign simulations verify discovery, logistics, charter completion and recovery; browser charts use actual links/counts. See [WORLDS.md](WORLDS.md).

Static HTML does not vary with URL queries. Workbox precache matching ignores query parameters so offline tagged game URLs resolve the correct game entry instead of the library fallback. The browser still receives its original query string; development speed helpers remain absent from production.
